4. FULL TRAINING AND INFERENCE DATA FLOW

Training:
  Current sample.frame_index -> exact Doosan state packing (1,60).
  Wrench from proprios.wrench at that frame -> indices 20:26, Fx,Fy,Fz,Tx,Ty,Tz.
  Existing normalize_quantile exactly once -> float32 normalized state.
  Dataset validates stats and emits int64 force_normalization=1.
  Existing collate stacks state and marker, packs image/language examples.
  Existing auto_cast converts float32 model tensors to bfloat16.
  Shared prepare_force_conditioning extracts normalized wrench and zeros both
  original state-projector inputs on channels 20:26 (unless explicit dual_path).
  Encoder -> feature -> fusion residual (B,6,1024).
  Training repeat_interleave repeats residual with the exact state/action order.
  dit_forward adds residual to t_projector(t_embedder(t)); original DiT/action
  output then predicts velocity for the existing flow-matching loss.
  Async prefix generation also receives the same residual.
  Auxiliary VLM choice/score loss remains force-free; force gradients originate
  from DiT action loss. Existing requires_grad-filtering optimizer includes all
  enabled trainable new parameters without a replacement trainer.

actions.semantic remains the converter's measured 7D semantic label, windowed
and temporally padded to (30,60); only real timesteps/channels 0:7 are loss-active.
No deltas are recomputed and no wrench enters labels. Existing loss code is
unchanged; incomplete horizons are excluded from its frequency loss.

Inference:
  DoosanClient packs raw current state and wrench_present=true.
  Encoder server requires wrench presence and valid stats, rejects an incoming
  normalization marker (raw-state API), performs matching float32 normalization
  once, emits the int64 marker, and calls model.generate.
  Generate uses the same forward/force preparation and same residual at every
  ODE step. Deployment loads complete encoder checkpoints strictly.
  Deployment selects Doosan's (30,60) mask with channels 0:7, then uses existing
  action denormalization. Generic embodiments keep the original generic mask.
  Direct model callers must provide normalized state and marker themselves.

5. FORCE NORMALIZATION SEMANTICS

Encoder input is ALREADY normalized, not raw N/Nm:
  clip(2 * ((raw-q01) / ((q99+1e-6)-q01)) - 1, -1, 1)
The torch server path matches the numpy dataset's float32 operation ordering.
No second normalization happens inside the encoder. Large finite observations
saturate at +/-1; raw zero is not necessarily normalized zero. The API marker
is explicit provenance, not a way to detect a caller falsely marking data.

Stats must use native XR-1 (1,60) layout, never copied converter 25D ordering.
Finite statistics are required, with q99>q01 at ALL six wrench slots. Missing,
zero-padded force stats, degenerate spans, malformed state/wrench, nonfinite
wrench, and values outside the normalized range produce errors.
Only test fixtures/verification use synthetic statistics. Use real training-split
stats consistently for train/validation/test/inference; none were read/invented.

The data contract remains BASE-frame [N,N,N,Nm,Nm,Nm] observations from
Doosan RobotStateRt.external_tcp_force, already controller-reset-compensated.
No offline tare, reset, gravity compensation, frame transform, contact gate, or
force-magnitude-derived contact label is introduced.
